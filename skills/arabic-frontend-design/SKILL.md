# التصميم الاحترافي للواجهات الأمامية العربية

صمّم الواجهة العربية كنظام قراءة واتخاذ قرار، لا كمجرد واجهة إنجليزية معكوسة. اجعل المعنى، أولوية المهمة، واتجاه القراءة أساس البنية قبل اختيار الألوان أو المؤثرات. اكتب النصوص العربية الطبيعية أولاً، ثم ابنِ المكوّنات والفراغات حول طولها الفعلي.

## 1. ابدأ بتشخيص المنتج

حدّد نوع الواجهة، المستخدم الأساسي، القرار الذي يجب أن يتخذه المستخدم، وأهم مسار عمل قبل كتابة أي JSX أو CSS. لخّص هذه العناصر في سطر واحد داخل وثيقة التصميم أو تعليق أعلى الصفحة الرئيسية.

| العنصر | ما يجب حسمه | معيار الجودة |
| --- | --- | --- |
| المستخدم | من يستخدم الواجهة وفي أي سياق | لا تبنِ تفاصيل لا تخدم مهمته الأساسية |
| المهمة | الإجراء الأكثر قيمة في الجلسة | يظهر الإجراء بوضوح دون البحث في القوائم |
| المحتوى | عربي فقط أم عربي/إنجليزي | لا تتكسر المحاذاة مع النص المختلط أو الأرقام |
| الحالة | ثابتة، مراقبة، أم تشغيلية | تعكس الألوان والرسائل حالة حقيقية ومفهومة |

## 2. اضبط RTL من الجذر

استخدم `dir="rtl"` و`lang="ar"` عند كون العربية هي لغة الواجهة الأساسية. فضّل الخصائص المنطقية في CSS مثل `margin-inline-start` و`padding-inline-end` و`inset-inline-start` بدلاً من `left` و`right`. طبّق المحاذاة البصرية بحسب المعنى، لا بحسب الاتجاه وحده: الأرقام، الشارات، التواريخ، الأكواد، ومؤشرات الحالة قد تحتاج مساحة LTR معزولة.

> لا تقلب كل شيء آلياً. يجب أن ينتقل ترتيب القراءة والتنقل إلى اليمين-يسار، بينما تبقى المخططات الزمنية، الأكواد، وعناصر الإدخال ذات البنية التقنية مفهومة بحسب طبيعتها.

| حالة مختلطة | التنفيذ الموصى به | تجنّب |
| --- | --- | --- |
| رقم هاتف أو معرّف | استخدم `dir="ltr"` على القيمة فقط | دمج الرقم مع نص عربي بلا عزل |
| كود أو أمر طرفية | استخدم خطاً أحادي العرض و`dir="ltr"` | قلب مسار الكود |
| بطاقة بيانات | اجعل العنوان يميناً والقيمة قابلة للعزل | محاذاة كل شيء يميناً بلا تمييز |
| أيقونة اتجاهية | استخدم النسخة الملائمة لـ RTL | إبقاء سهم «التالي» متجهاً إلى اليمين |

## 3. ابنِ تسلسلاً بصرياً واضحاً

رتّب الصفحة من الأهم إلى الأقل أهمية: عنوان يحدّد الوضع أو المهمة، ثم الإجراء التالي، ثم الأدلة أو التفاصيل. لا تجعل كل البطاقات متساوية الحجم والوزن. استخدم الحقول، المساطر، العناوين الصغيرة، والأرقام المرجعية عندما تكون الواجهة تحليلية أو تشغيلية.

استخدم خط عرض عربي واضح للنصوص البارزة، وخطاً عملياً للنصوص الطويلة. وفّر تبايناً كافياً بين العنوان، الشرح، والبيانات الثانوية. لا تضع نصاً عربياً صغيراً فوق صورة متغيرة الإضاءة من دون طبقة خلفية تضمن المقروئية.

| الطبقة | التوجيه | مثال |
| --- | --- | --- |
| العنوان | قصير، مباشر، كبير، ومسافة أسطر مضبوطة | «راجع التغطية قبل النشر» |
| الإجراء | فعل محدّد مرتبط بحالة | «سجّل نقطة تحقق» |
| الشرح | جملة واحدة تشرح السبب أو الأثر | «تتضمن التغطية الواجهة ومسارات التفاعل.» |
| البيانات الثانوية | حجم أصغر وتباين أقل دون أن تصبح باهتة | الوقت، المصدر، أو حالة المزامنة |

## 4. أنشئ نظام ألوان دلالياً

اختر لوناً أساسياً واحداً للتركيز والإجراء، ولوناً للتحقق أو النجاح، ولوناً مستقلاً للتحذير أو الحالة المفتوحة. اربط اللون بمعناه في كامل المنتج ولا تستعمله كزينة متكررة. اجعل الخلفيات محايدة ودافئة أو باردة وفق هوية العلامة، ثم اختبر التباين مع النصوص العربية ذات الأحرف الدقيقة.

| الدلالة | استخدام مناسب | قاعدة تنفيذ |
| --- | --- | --- |
| أساسي | الإجراء التالي أو العنصر النشط | لا تستخدمه لأكثر من فعل رئيسي في المجال نفسه |
| تحقق | دليل مكتمل أو حالة سليمة | أضف نصاً أو رمزاً؛ لا تعتمد على اللون وحده |
| تحذير | معلومة ناقصة أو سؤال مفتوح | اذكر ما الذي يحل الحالة بوضوح |
| محايد | بنية الصفحة والمعلومات الثانوية | حافظ على تباين القراءة لا على الزخرفة |

## 5. صمّم المكوّنات قبل الصفحة

استخدم المكونات الموجودة في القالب أولاً، ثم وسّعها بأسلوب موحّد. حدّد أحجاماً ثابتة للأزرار، حقول الإدخال، الشارات، الفواصل، وحالات التحميل. اجعل كل مكوّن يشرح وظيفته بالعربية السليمة ويحتوي حالة فارغة، حالة خطأ، وحالة نجاح عندما تكون مطلوبة.

لا تستخدم عناصر وهمية تبدو كأنها تعمل. إذا كانت ميزة غير متاحة، عطّلها أو اعرض إشعاراً قصيراً يوضح ما ينقص. لا تضع تقييمات، شهادات، أو مراجعات مستخدمين مصطنعة.

| مكوّن | الحد الأدنى | سؤال المراجعة |
| --- | --- | --- |
| زر | فعل، حالة تعطيل، وتركيز لوحة مفاتيح | هل يصف الفعل بدلاً من «اضغط هنا»؟ |
| بطاقة | عنوان، محتوى، وحدّ بصري هادئ | هل تضيف قراراً أم مجرد زخرفة؟ |
| نموذج | تسمية ظاهرة، خطأ قريب، وتلميح مفيد | هل يستطيع قارئ الشاشة فهمه؟ |
| جدول أو سجل | عناوين، ترتيب، وقيم RTL/LTR معزولة | هل يمكن مسحه بصرياً من اليمين إلى اليسار؟ |

## 6. صمّم الاستجابة لا التصغير

صمّم الجوال كمسار قراءة مستقل. على الشاشات الصغيرة، اجعل المهمة الحالية والإجراء التالي في البداية، ثم التفاصيل القابلة للطي أو التمرير. لا تقلّص لوحة التحكم المكتبية ببساطة؛ أعد ترتيب الحقول، وخفّف كثافة البيانات، وحافظ على الأزرار ضمن مساحة لمس مريحة.

| نقطة تحقق | سطح المكتب | الجوال |
| --- | --- | --- |
| التنقل | شريط جانبي أو مسار سياقي دائم | قائمة قابلة للفتح أو شريط مختصر |
| المحتوى | حقول متجاورة عند وجود علاقة واضحة | تسلسل عمودي بحسب أولوية المهمة |
| الجداول | أعمدة كاملة مع تمرير أفقي عند الضرورة | بطاقات بيانات أو أعمدة جوهرية فقط |
| الإجراءات | أزرار بجوار المحتوى | زر رئيسي واضح في بداية القسم أو نهايته |

## 7. نفّذ الحركة كاستجابة لا كاستعراض

حرّك `opacity` و`transform` فقط في التفاعلات المعتادة. اجعل دخول القوائم واللوحات سريعاً بين 180 و240 ميلي ثانية، وأضف تأثير ضغط بسيط للأزرار. احترم `prefers-reduced-motion`، ولا تستخدم حركة مستمرة إلا إذا كانت تعبّر عن حالة تشغيل حقيقية.

استخدم الحركة لتأكيد أن النظام استجاب: بعد حفظ نموذج، بعد تسجيل نقطة تحقق، أو عند فتح مفتش للسياق. لا تستخدمها لتأخير المحتوى أو إخفاء ضعف البنية.

## 8. راجع الوصول والجودة قبل التسليم

اختبر اتجاه لوحة المفاتيح، حلقة التركيز، تباين النص، أحجام اللمس، وحالات الخطأ على سطح المكتب والجوال. راجع النصوص العربية مع إدخال طويل، واسم إنجليزي، ورقم، وتاريخ؛ ثم اختبر صفحة كاملة بلقطة شاشة قبل التسليم.

| اختبار نهائي | النتيجة المقبولة |
| --- | --- |
| التركيز | يظهر بوضوح ولا يختفي داخل الخلفيات |
| التباين | يمكن قراءة النص في كل حالة وخلفية |
| RTL | ترتيب القراءة، الأسهم، وهوامش البداية/النهاية صحيحة |
| النص المختلط | لا تنكسر الأرقام أو المعرفات أو التواريخ |
| الجوال | لا يوجد تمرير أفقي غير مقصود ولا أزرار صغيرة |
| الصدق | لا توجد بيانات أو نتائج أو مراجعات مصطنعة |

## 9. تجنّب هذه الأنماط

تجنّب تحويل الواجهة إلى شبكة بطاقات متشابهة، والخلفيات المتدرجة البنفسجية الافتراضية، والدوائر المفرطة، وخط Inter بوصفه الخيار الوحيد. لا تجعل التصميم التقني مظلماً أو متوهجاً تلقائياً؛ اختره فقط عندما يخدم سياق المنتج. لا تترجم العبارات حرفياً إذا كان الفعل العربي أو ترتيب الجملة سيبدو مصطنعاً.

## سير العمل المختصر

1. حدّد المهمة والمستخدم والسياق.
2. اختر اتجاهاً بصرياً واحداً واكتب مبادئه.
3. فعّل RTL من الجذر واعزل القيم التقنية عند الحاجة.
4. ابنِ الهيكل والمكونات والحالات قبل الزخرفة.
5. اختبر سطح المكتب والجوال والوصول والنص المختلط.
6. سلّم فقط بعد أن يصبح الإجراء التالي والحالة والدليل واضحين من النظرة الأولى.
